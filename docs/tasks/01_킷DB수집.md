# 작업 지시서 01 — 건프라 킷 DB 수집

이 문서 하나만 읽고 작업할 수 있게 작성되어 있다. 다른 문서를 참조할 필요 없다.

---

## 1. 목적

건담 프라모델(건프라) 제품 카탈로그를 구조화된 데이터로 수집한다. 커뮤니티 사이트의 킷 정보 페이지와 검색 기능의 기반 데이터가 된다.

**커버리지가 품질보다 중요하다.** 상세 정보가 얕아도 제품이 목록에 있는 것이 낫다. 사용자가 검색했는데 자기 킷이 없으면 다시 오지 않는다. 반대로 정보가 부실한 것은 나중에 채울 수 있다.

---

## 2. 절대 제약

어기면 결과물 전체를 폐기해야 한다. 반드시 지킬 것.

### 2.1 사실 필드만 수집한다

수집 대상 — 제품명, 등급, 스케일, 발매일, 정가(엔화, 국내발매가=엔화*12), 품번, 시리즈, 기체 형식번호.

**수집 금지** — 위키나 리뷰 사이트의 **서술 문장**. 제품 설명, 평가, 특징 요약, 개봉기 내용 등 문장 형태의 텍스트는 한 줄도 가져오지 않는다.

이유 — 제품명·날짜·가격 같은 사실 정보는 저작권 대상이 아니지만, 서술 텍스트는 저작권 대상이다. 특히 CC BY-SA 계열 라이선스는 전염성이 있어 파생 데이터베이스까지 같은 조건으로 공개해야 할 수 있다.

설명 필드가 필요하면 **비워두고 넘어간다.** 직접 요약해서 채우려 하지도 말 것.

### 2.2 이미지를 수집하지 않는다

박스아트, 제품 사진, 런너 사진 전부 제외. 제조사 저작물이다. 이미지 URL도 저장하지 않는다.

### 2.3 나무위키를 소스로 쓰지 않는다

비영리 조건이 붙은 라이선스라 광고나 유료화 계획이 있는 프로젝트에서는 쓸 수 없다. 참고용으로 읽는 것도 하지 않는다. 사실이 다른 소스에도 있으면 그쪽에서 가져온다.

### 2.4 남의 데이터베이스를 통째로 복제하지 않는다

개인 리뷰 사이트나 전문 DB 사이트의 데이터를 일괄 덤프하는 방식은 데이터베이스 제작자의 권리 문제를 만든다. 여러 소스에서 개별 사실을 교차 수집하는 방식으로 접근한다.

---

## 3. 수집 범위

### 포함

- **건담 시리즈 프라모델만.** 반다이 건프라 라인
- 전 등급, 구판 포함
- 국내 미발매 해외 한정판도 포함

### 제외

- 반다이의 건담 외 라인 (마크로스, 엘가임, 30MM, 피규어라이즈 등)
- 타 메이커 (코토부키야, 굿스마일 등)
- 완성품 피규어, 액션 피규어 (프라모델이 아님)
- 무장 세트·확장 파츠는 **포함하되** 기체 연결 없이 등록

---

## 4. 출력 스키마

### 4.1 `kits.csv`

| 컬럼 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `temp_id` | string | O | 이 파일 내 고유 식별자. `K0001` 형식 |
| `name_ko` | string | O | 한국어 제품명. 정식 표기 |
| `name_ja` | string | | 일본어 제품명 |
| `name_en` | string | | 영문 제품명 |
| `grade_family` | string | O | 아래 목록 중 하나만 |
| `scale` | string | O | `1/144`, `1/100`, `1/60`, `논스케일` |
| `series` | string | | 작품명 (예: 기동전사 건담 역습의 샤아) |
| `unit_model_numbers` | string | | 기체 형식번호. 여러 개면 `;`로 구분 |
| `product_no` | string | | 품번 |
| `release_date` | date | | `YYYY-MM-DD`. 일자 미상이면 `YYYY-MM-01` |
| `price_jpy` | integer | | 정가 (엔, 세금 포함 여부 무관) |
| `is_limited` | boolean | O | 한정판 여부 |
| `limited_channel` | string | | `프리미엄반다이` / `건담베이스` / `이벤트` / `일반` |
| `base_kit_temp_id` | string | | 외형 변형인 경우 원본 킷의 temp_id |
| `data_source` | string | O | 출처 (도메인 수준) |
| `confidence` | string | O | `high` / `medium` / `low` |

### 4.2 `grade_family` 허용값

이 목록 외의 값을 쓰지 않는다. 애매하면 `confidence`를 `low`로 두고 가장 가까운 값을 쓴 뒤 `notes.md`에 기록한다.

```
HG      RG      MG      MGEX    MGSD
PG      EG      RE100   FM      SD      구판
```

**분류 규칙**

- HGUC, HGCE, HGAC, HGBF, HGIBO, HGWFM 등 **접미어가 붙은 모든 HG 계열은 `HG`로 통일한다.** 접미어의 작품 정보는 `series` 컬럼이 담당한다
- SDCS, BB전사, SD EX-STANDARD, 크로스실루엣 → `SD`
- PG Unleashed → `PG`
- **MGSD는 독립 값이다.** MG나 SD로 넣지 않는다
- Full Mechanics → `FM`
- RE/100 → `RE100`
- 등급 표기가 없는 1/144, 1/100 구판 → `구판`

### 4.3 `units.csv` (기체)

| 컬럼 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `model_number` | string | O | `RX-78-2`, `MSN-04`, `XVX-016` 등. 대문자, 하이픈 유지 |
| `name_ko` | string | O | 한국어 기체명 |
| `name_ja` | string | | 일본어 기체명 |
| `name_en` | string | | 영문 기체명 |
| `series` | string | | 등장 작품 |

킷과 기체는 다대다 관계다. `kits.csv`의 `unit_model_numbers`가 이 파일의 `model_number`를 참조한다.

### 4.4 `notes.md`

판단이 애매했던 케이스를 기록한다. 이게 다음 작업의 입력이 된다.

- 어느 등급으로 넣을지 애매했던 제품
- 소스 간 정보가 충돌한 경우 (어느 쪽을 택했고 왜)
- 수집이 불가능했던 구간과 이유
- 소스별 표 구조 차이

---

## 5. 예외 처리 규칙

| 케이스 | 처리 |
|---|---|
| **재판** (내용 동일, 발매일만 다름) | **별도 행으로 만들지 않는다.** 초판 정보만 기록. 재판 이력은 이번 작업 범위 밖 |
| **외형 변형** (클리어, 티타늄, 메탈릭, Ver.애니메컬러) | 별도 행. `base_kit_temp_id`로 원본 연결 |
| **유통 한정** (프리미엄반다이 등) | 별도 행. `is_limited=true`, `limited_channel` 기입 |
| **세트 킷** (기체 여러 개) | 한 행. `unit_model_numbers`에 `;`로 나열 |
| **무장 세트·확장 파츠** | 한 행. `unit_model_numbers` 비움 |
| **변칙 스케일** (HG 1/100 등) | **제외하지 않는다.** `scale`에 실제 값 기입 |
| **발매 예정 제품** | 포함. `release_date`에 예정일, `confidence=low` |
| **발매 취소 제품** | 제외 |
| **정보가 부족한 구판** | 포함. 아는 필드만 채우고 `confidence=low` |

**판단 원칙** — 넣을지 말지 애매하면 **넣는다.** 커버리지가 우선이고, 잘못 들어간 건 나중에 지우면 되지만 빠진 건 발견되지 않는다.

---

## 6. 소스 우선순위

1. 제조사 공식 제품 정보 (사실 데이터의 1차 출처)
2. 영문 위키 계열 중 CC BY-SA 라이선스인 곳 — **사실 필드만**
3. 유통사 상품 페이지 (품번, 정가, 발매일에 강함)

각 행의 `data_source`에 어디서 왔는지 도메인 수준으로 남긴다. 여러 소스를 조합했으면 주된 곳 하나.

**소스 간 정보가 다르면** 공식 > 유통사 > 위키 순으로 채택하고 `notes.md`에 기록한다.

---

## 7. 작업 순서

한 번에 다 하려 하지 말 것. 등급 단위로 나눠서 진행하고, 각 단위가 끝날 때마다 파일을 내보낸다.

```
1차: MG, MGEX, MGSD, PG    (물량 적고 정보 정확. 형식 검증용)
2차: RG, FM, RE100, EG
3차: HG                    (물량 최대)
4차: SD 계열
5차: 구판
```

**1차를 마치면 멈추고 결과를 검증받는다.** 형식이 틀린 채로 3차까지 가면 전부 다시 해야 한다.

---

## 8. 검증

각 차수 산출물에 대해 아래를 확인한다.

- [ ] `grade_family` 값이 허용 목록 밖인 행이 0건인가
- [ ] `temp_id` 중복이 없는가
- [ ] `base_kit_temp_id`가 존재하지 않는 id를 가리키지 않는가
- [ ] `unit_model_numbers`의 값이 `units.csv`에 전부 있는가
- [ ] `scale` 값이 허용 형식인가
- [ ] 서술 문장이 들어간 셀이 있는가 (**있으면 즉시 제거**)
- [ ] 이미지 URL이 들어간 셀이 있는가 (**있으면 즉시 제거**)
- [ ] 무작위 10건을 골라 공식 정보와 대조했을 때 일치하는가

마지막 항목이 실질적인 품질 검사다. 반드시 수행한다.

---

## 9. 하지 말 것

- 스키마에 없는 컬럼을 임의로 추가하지 않는다. 필요하면 `notes.md`에 제안만
- 데이터를 "정리"한다며 제품명을 임의로 축약하거나 통일하지 않는다. 정식 표기 그대로
- 등급 접미어를 살리지 않는다 (HGUC → HG)
- 설명 필드를 만들어 채우지 않는다
- 인기 순위, 평점, 추천 같은 주관적 필드를 추가하지 않는다
- 수집 대상 범위를 넓히지 않는다. 반다이 타 라인은 제외
