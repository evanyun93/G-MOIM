## 역할

**Antigravity는 당분간 킷 영역 전담이다.**

| 담당 | 내용 | 착수 시점 |
|---|---|---|
| 킷 카탈로그 수집 | 01_v2 스키마로 전 등급 수집 | **지금** |
| 킷·기체 페이지 구현 | 수집한 데이터를 보여주는 페이지 | **스택 선정(설계 노드 4.1) 확정 후.** 별도 지시서로 시작 |

페이지 구현은 프레임워크와 정적 생성 방식이 정해져야 할 수 있다. 그 전에 페이지 코드, 프레임워크 선택, 프로젝트 초기화(`npm init` 등)를 하지 않는다. 스택에 대한 의견이 있으면 `notes.md`에 남기는 것까지만 한다.

## 3. 작업 환경 규칙

### 3.1 작업 위치

- 작업 디렉터리는 **`C:\dev\G-MOIM-kit-db`** (워크트리)
- `C:\dev\G-MOIM`은 다른 세션이 `main`에서 사용 중이다. **그 폴더에서 파일을 쓰거나 브랜치를 바꾸지 않는다**

### 3.2 git

- 허용 — `status`, `diff`, `log`, `show` (읽기만)
- 금지 — `commit`, `push`, `merge`, `rebase`, `checkout`, `switch`, `reset`, `stash`, `worktree`
- 커밋은 사람이 검증 후 한다

### 3.3 쓰기 허용 경로

**`data/kits/raw/` 아래만.** `docs/`, `README.md`, `CLAUDE.md`, 설정 파일을 수정하지 않는다.

### 3.4 산출물 경로 (01_v2 13장을 대체)

```
data/kits/raw/
├── progress.md                 진행 기록 (01_v2 14장 대신 여기에)
├── units.csv                   등급 공통 누적 단일 파일

    ├── kits.csv
```

등급마다 같은 구조의 폴더를 만든다(`RG/`, `PG/` …). 검증을 통과한 파일은 사람이 `data/kits/`로 옮긴다.

### 3.5 파일 형식

- UTF-8 (BOM 없음), 줄바꿈 LF
- CSV는 쉼표 구분. 쉼표나 따옴표가 들어간 값은 큰따옴표로 감싼다

### 3.6 소스 접근

- 나무위키는 **브라우저로 열지도 않는다**
- 사이트의 이용약관과 robots.txt를 따른다. 페이지를 연속으로 열 때는 간격을 둔다
- 로그인이 필요하거나 차단된 페이지를 우회하지 않는다. `확인불가`로 기록한다

## 5. 지금 할 일 — MG 목록(4-1) 완결

### 5.1 목표

MG 전체 목록을 **연도 × 유통 채널** 단위로 빈틈 없이 완성한다. 끝나면 멈추고 보고한다. **CSV(4-2)는 시작하지 않는다.**

### 5.2 절차

1. **`data/kits/raw/MG/coverage_checklist.md`를 새로 만든다.** 형식은 아래와 같다. 01_v2 4장 형식에 `유통`, `출처` 칸을 더했다. 한정 유통이 40% 가까이 되므로 목록 단계부터 채널을 구분한다. `출처`에는 도메인 수준으로 적는다.

   ```markdown
   | # | 제품명 | 발매연도 | 유통 | 출처 | 수집 여부 |
   |---|---|---|---|---|---|
   | 1 | MG RX-78-2 건담 | 1995 | 일반 | bandai-hobby.net | [ ] |
   ```

   `유통` 허용값: `일반` `프리미엄반다이` `건담베이스` `이벤트` `미확인`

2. **연도별 커버리지 표를 만든다.** MG가 시작된 1995년부터 2026년까지 한 해도 빼지 않는다(5.3 형식)
3. **재조사 대상을 뽑는다.**
   - 일반 유통이 0건인 연도
   - 앞뒤 연도에 비해 절반 이하로 떨어진 연도
   - **2018~2026년 일반 유통분은 전부.** 이전 보고에서 가장 의심스러운 구간이다
4. **재조사 대상 연도는 독립된 소스 2곳 이상에서 교차 확인한다.** 예: 제조사 공식 라인업과 유통사의 등급별 카테고리(페이지네이션 끝까지)
5. **중복을 정리한다.** 한국어·일본어 표기 차이로 같은 제품이 두 번 들어간 경우를 찾는다. 합친 내역은 `notes.md`에 남긴다

### 5.3 출력 계약 — 가장 중요

**"찾지 못함"과 "존재하지 않음"을 구분한다.**

연도×채널 칸의 상태는 반드시 셋 중 하나다.

| 상태 | 뜻 | 필요한 근거 |
|---|---|---|
| `확인` | n건 존재 | 확인한 소스 |
| `부재확인` | 0건. 해당 연도의 전체 목록을 실제로 열람해 없음을 확인 | 열람한 페이지 |
| `확인불가` | 소스 접근 실패, 페이지 없음, 차단 등 | 시도한 소스와 실패 사유 |

- **0을 쓸 수 있는 건 `부재확인`일 때뿐이다.** 근거 없는 0이 하나라도 있으면 결과물 전체를 반려한다
- `확인불가` 칸의 건수는 `0`이 아니라 `?`로 쓴다

`coverage_checklist.md` 맨 위에 아래 표를 둔다.

```markdown
## MG 연도별 커버리지

| 연도 | 일반 | 한정 | 일반 상태 | 한정 상태 | 근거 |
|---|---|---|---|---|---|
| 2021 | 6 | 11 | 확인 | 확인 | 공식 라인업, 유통사A 카테고리 |
| 2022 | ? | 9 | 확인불가 | 확인 | 일반: 공식 라인업 2022 페이지 404, 유통사A 페이지네이션 3쪽 이후 차단 |
```

`notes.md`에는 **시도한 소스 기록**을 남긴다. 실패한 시도도 전부 적는다.

```markdown
## 소스 시도 기록

| 소스 (도메인+경로) | 커버 연도 | 결과 | 비고 |
|---|---|---|---|
```

### 5.4 멈출 때 보고할 것

채팅으로 아래를 보고하고 멈춘다.

- MG 총 종수 (일반 / 한정), 이전 보고치 358종(한정 143종) 대비 차이와 그 이유
- `확인불가` 칸 목록과 각 사유
- 이전 보고의 "2022년 일반 유통 0건"의 원인 판단
- 중복으로 합친 건수
- 판단이 애매했던 항목 수 (`notes.md` 참조)
- 수정·생성한 파일 목록

`확인불가`가 남아 있으면 **"완료"라고 쓰지 않는다.** "완료 (확인불가 N칸 남음)"처럼 남은 것을 함께 쓴다.
