# 작업 지시서 02 — 별칭 사전 수집

이 문서 하나만 읽고 작업할 수 있게 작성되어 있다.

**선행 조건** — 지시서 01(킷 DB 수집)의 산출물 `kits.csv`, `units.csv`가 있어야 한다.

---

## 1. 목적

건프라 커뮤니티 사이트에서 두 기능의 정확도를 좌우하는 사전을 만든다.

**검색** — 사용자가 치는 말과 정식 제품명이 다르다. "사자비"로 검색했을 때 "MG 1/100 사자비 Ver.Ka"가 나와야 한다.

**자동 태그 매칭** — 사용자가 작례 글을 쓸 때 제목과 본문에서 킷 이름을 추출해 자동으로 후보를 제시한다. 이 기능의 정확도는 사실상 이 사전의 품질이 전부다.

한국 건프라 커뮤니티는 같은 기체를 부르는 방식이 극단적으로 갈린다. 한글 음차가 여러 개 공존하고, 일본어 원문과 영문 표기가 섞이고, 형식번호로만 부르는 경우도 많다. 이 편차를 전부 담는 것이 이 작업이다.

---

## 2. 출력 스키마

### `aliases.csv`

| 컬럼 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `entity_type` | string | O | `kit` / `unit` / `series` |
| `entity_key` | string | O | `unit`이면 `model_number`, `kit`이면 `temp_id`, `series`면 작품명 |
| `alias` | string | O | 별칭 한 개 |
| `lang` | string | O | `ko` / `ja` / `en` / `code` |
| `alias_type` | string | O | 아래 목록 중 하나 |
| `confidence` | string | O | `high` / `medium` / `low` |

한 행에 별칭 하나다. 쉼표로 여러 개를 몰아넣지 않는다.

### `alias_type` 허용값

| 값 | 설명 | 예 |
|---|---|---|
| `official` | 정식 표기 | 사자비 |
| `transliteration` | 음차 변형 | 사쟈비, 사자비 |
| `abbreviation` | 약칭 | 뉴건, 쌍제타 |
| `model_code` | 형식번호 | MSN-04 |
| `nickname` | 커뮤니티 통칭 | 붕뚀 |
| `foreign` | 외국어 표기 | サザビー, Sazabi |
| `common_typo` | 자주 나는 오타·띄어쓰기 변형 | 사자비버카 |

## 3. 수집할 변형 유형

각 기체와 킷에 대해 아래를 체계적으로 훑는다.

### 3.1 한글 음차 편차

일본어 발음을 한글로 옮기는 방식이 여러 가지다. 실제 커뮤니티에서 쓰이는 것을 모은다.

- 장음 처리 차이
- 유성음·무성음 표기 차이
- 외래어 표기법 준수 여부 차이

**주의** — 이론적으로 가능한 조합을 만들어내지 말고, **실제로 쓰이는 것만** 넣는다. 자동 생성한 음차 변형은 오매칭의 주요 원인이다.

### 3.2 형식번호

- 정식 표기 (`RX-78-2`)
- 하이픈 없는 표기 (`RX782`)
- 공백 표기 (`RX 78 2`)

형식번호는 세 형태를 모두 넣는다. 이건 기계적으로 생성해도 안전하다.

### 3.3 약칭과 통칭

커뮤니티에서만 통하는 말이 많다. 이게 사전의 가장 큰 가치다. 실제 게시판을 확인해서 수집한다.

### 3.4 외국어 표기

- 일본어 원문 (가타카나)
- 영문 표기

### 3.5 등급 접두어 조합

킷 레벨 별칭에 필요하다. 지시서 01에서 등급 접미어를 `HG`로 통일했기 때문에, 사용자가 치는 `HGUC`가 검색에 잡히려면 여기서 보완해야 한다.

- `HGUC 자쿠` → 해당 킷의 별칭
- `HGCE 프리덤`, `HGWFM 에어리얼` 등 작품별 접미어 조합

**이 항목이 이번 작업에서 가장 중요하다.** 등급 정규화의 대가로 생긴 검색 공백을 메우는 부분이다.

---

## 4. 절대 제약

### 4.1 과도한 별칭은 해롭다

별칭이 많을수록 좋은 게 아니다. **오매칭은 미매칭보다 나쁘다.** 사용자가 "건담" 작례를 올렸는데 엉뚱한 킷이 태그되면 신뢰를 잃는다.

아래는 넣지 않는다.

- 두 글자 이하 (`건담`, `자쿠` 단독) — 너무 많은 대상에 걸린다
- 여러 기체에 공통으로 해당하는 말 (`커스텀`, `改`, `Ver.Ka` 단독)
- 실제 사용 사례를 확인하지 못한 추측 표기
- 오타를 기계적으로 생성한 것 (자주 나는 것 소수만)

애매하면 `confidence=low`로 넣고 `notes.md`에 남긴다. 나중에 오매칭 데이터를 보고 걸러낸다.

### 4.2 서술 텍스트를 수집하지 않는다

지시서 01과 동일하다. 별칭이라는 단어·구 단위만 수집하고, 설명 문장은 한 줄도 가져오지 않는다.

### 4.3 나무위키를 소스로 쓰지 않는다

비영리 라이선스 조건 때문이다. 참고용으로 읽는 것도 하지 않는다.

**별칭 수집의 주 소스는 위키가 아니라 커뮤니티 게시판이다.** 실제 사용례를 관찰하는 방식으로 접근한다.

## 5. 우선순위

물량이 많으므로 가치 순으로 진행한다.

```
1차: unit 별칭 — 인기 기체 상위 100기
     (RX-78-2, 사자비, 뉴건담, 자쿠II, 프리덤, 배리에이션 다수 기체 등)
2차: kit 별칭 — MG, RG, PG 등급
3차: unit 별칭 — 나머지 전체
4차: kit 별칭 — HG 등급
5차: series 별칭
```

**1차를 마치면 멈추고 검증받는다.** 형식과 판단 기준이 맞는지 확인한 뒤 진행한다.

인기 기체 판단은 킷이 여러 등급으로 나온 기체를 기준으로 한다. `kits.csv`에서 같은 `unit_model_numbers`를 가진 킷이 많은 순으로 정렬하면 대략 맞는다.

## 6. 검증

- [ ] `entity_key`가 `kits.csv` 또는 `units.csv`에 존재하는가
- [ ] `alias_type`, `lang`, `confidence` 값이 허용 목록 안인가
- [ ] 같은 `entity_key`에 동일한 `alias`가 중복되지 않는가
- [ ] **서로 다른 `entity_key`에 동일한 `alias`가 붙은 경우가 있는가** — 있으면 전부 검토. 오매칭 직결
- [ ] 두 글자 이하 별칭이 있는가 (있으면 제거)
- [ ] 무작위 20건을 골라 실제 커뮤니티에서 그 표기가 쓰이는지 확인

네 번째와 마지막 항목이 실질적인 품질 검사다. 반드시 수행한다.

---

## 7. 하지 말 것

- 음차 변형을 규칙으로 자동 생성하지 않는다 (형식번호 표기 변형만 예외)
- 스키마에 없는 컬럼을 추가하지 않는다
- 정식 표기를 임의로 판단해 바꾸지 않는다. 그건 `kits.csv`, `units.csv`의 몫
- 기체와 킷을 섞지 않는다. `RX-78-2`는 `unit`, `MG RX-78-2 Ver.3.0`은 `kit`
- 별칭 개수를 목표로 삼지 않는다. 정확도가 목표다
