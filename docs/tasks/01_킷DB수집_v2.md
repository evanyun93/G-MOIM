# 작업 지시서 01 — 건프라 킷 DB 수집 (v2)

이 문서 하나만 읽고 작업할 수 있게 작성되어 있다. 다른 문서를 참조할 필요 없다.

**v1 대비 변경** — 전수 수집 절차 신설(4장), 품번 규칙 강화(5장), 재판 이력 수집 추가, units 누적 관리, 표기 정규화 규칙. v1으로 수집한 1·2차 결과는 폐기하지 말고 대조용으로 보관한다.

---

## 1. 목적

건담 프라모델(건프라) 제품 카탈로그를 구조화된 데이터로 수집한다.

**커버리지가 상세 정보보다 우선한다.** 사용자가 검색했는데 자기 킷이 없으면 다시 오지 않는다. 정보가 얕은 것은 나중에 채울 수 있지만, 목록에서 빠진 것은 아무도 발견하지 못한다.

**정확도가 분량보다 우선한다.** 확인되지 않은 값은 채우지 말고 비운다. 빈 칸은 나중에 채울 수 있지만, 그럴듯한 오답은 영원히 발견되지 않는다.

이 두 원칙이 충돌하면 — **행은 만들고 칸은 비운다.**

---

## 2. 절대 제약

어기면 결과물 전체를 폐기해야 한다.

### 2.1 사실 필드만 수집한다

수집 대상 — 제품명, 등급, 스케일, 발매일, 정가, 품번, 시리즈, 기체 형식번호.

**수집 금지** — 위키·리뷰 사이트의 **서술 문장**. 제품 설명, 평가, 특징 요약을 한 줄도 가져오지 않는다. 설명 필드가 필요하면 **비워두고 넘어간다.** 직접 요약해서 채우지도 않는다.

이유 — 사실 정보는 저작권 대상이 아니지만 서술 텍스트는 대상이다. CC BY-SA 계열은 전염성이 있어 파생 데이터베이스까지 같은 조건으로 공개해야 할 수 있다.

### 2.2 이미지를 수집하지 않는다

박스아트, 제품 사진, 런너 사진 전부 제외. 이미지 URL도 저장하지 않는다.

### 2.3 나무위키를 소스로 쓰지 않는다

비영리 조건 라이선스라 광고·유료화 계획이 있는 프로젝트에서 쓸 수 없다. 참고용으로 읽는 것도 하지 않는다.

### 2.4 값을 추측해서 채우지 않는다

**v1에서 가장 크게 문제가 된 항목이다.** 상세는 5장.

---

## 3. 수집 범위

**포함** — 반다이 건담 시리즈 프라모델만. 전 등급, 구판 포함. 국내 미발매 해외 한정판 포함.

**제외** — 반다이의 건담 외 라인(마크로스, 엘가임, 30MM, 피규어라이즈, 에반게리온 등), 타 메이커, 완성품 피규어.

**무장 세트·확장 파츠는 포함한다.** 기체 연결 없이 등록하되, 대상 킷이 있으면 `parent_kit_temp_id`로 연결한다(6장 참조).

---

## 4. 전수 수집 절차 (신설 — 가장 중요)

v1에서는 유명 킷 위주로 골라 담는 결과가 나왔다. MG 커버리지가 12% 수준이었다. 이를 막기 위해 **목록 확보를 수집과 분리한다.**

### 4-1단계. 라인업 목록부터 만든다

수집 대상 등급의 **전체 제품 목록**을 먼저 확보한다. 이 단계에서는 제품명과 발매 연도만 있으면 된다. 상세 정보는 수집하지 않는다.

목록은 `coverage_checklist.md`에 아래 형식으로 작성한다.

```markdown
## MG (전체 NNN종)

| # | 제품명 | 발매연도 | 수집 여부 |
|---|---|---|---|
| 1 | MG RX-78-2 건담 | 1995 | [ ] |
| 2 | MG MS-06S 샤아 전용 자쿠 II | 1995 | [ ] |
...
```

**목록이 끝나기 전에는 CSV 작성을 시작하지 않는다.**

### 4-2단계. 목록 전수에 대해 행을 만든다

체크리스트의 **모든 항목**에 대해 `kits.csv`에 행을 만든다. 예외 없다.

정보를 찾지 못한 필드는 **비워두고** `confidence=low`로 표시한다. 행 자체를 빠뜨리지 않는다.

### 4-3단계. 대조

작업 종료 시 체크리스트 항목 수와 CSV 행 수가 일치하는지 확인한다. 불일치하면 어느 항목이 빠졌는지 `notes.md`에 기록한다.

### 목록 확보 시 참고

- 등급별 공식 라인업 페이지 또는 발매 연표
- 유통사의 등급별 카테고리 목록 (페이지네이션 끝까지)
- 연도별로 나눠서 훑으면 누락이 줄어든다

**목록 단계에서 "유명한 것만"이라는 판단을 하지 않는다.** 무명 킷, 인기 없는 킷, 오래된 킷일수록 다른 곳에서 찾기 어려워 이 DB의 가치가 커진다.

## 5. 품번 규칙 (강화)

### 5.1 확인한 것만 기입한다

품번은 **실제로 해당 제품 페이지에서 확인한 경우에만** 기입한다. 확인하지 못했으면 **비운다.**

빈 품번은 나중에 채울 수 있다. 틀린 품번은 아무도 발견하지 못한 채 DB에 남는다.

### 5.2 절대 금지 — 인접 번호 추정

**파생 킷의 품번을 원본 킷 품번에서 ±1 해서 만들어내지 않는다.**

v1 결과에서 반복적으로 관찰된 패턴이다.

```
PG 엑시아          5057754
PG 엑시아 라이팅    5057755   ← 원본 +1
EG RX-78-2        5061611
EG 건담베이스 컬러  5061612   ← 원본 +1
```

실제 반다이 품번은 발매 시기와 라인에 따라 부여되며, 파생 킷이 원본과 연번인 경우는 오히려 드물다. 검증 결과 실제와 불일치한 사례도 확인됐다.

**같은 원칙이 발매일과 가격에도 적용된다.** 원본과 같은 날짜, 원본에서 유추한 가격을 쓰지 않는다.

### 5.3 품번 체계 참고

- `00xxxxx`, `01xxxxx`, `02xxxxx` — 2018년 이전 반다이 체계
- `50xxxxx`, `51xxxxx` — 2018년 이후 반다이 스피리츠 체계

**발매일이 2018년 이전인데 품번이 `50`으로 시작하면 재판 품번이다.** 이 경우 6장의 재판 처리 규칙을 따른다. 초판 품번을 찾지 못하면 품번을 비우고 재판 정보를 `kit_releases.csv`에 기록한다.

## 6. 출력 스키마

### 6.1 `kits.csv`

| 컬럼 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `temp_id` | string | O | `K0001` 형식. 차수 간 이어서 부여 |
| `name_ko` | string | O | 한국어 제품명. 정식 표기 |
| `name_ja` | string | | 일본어 제품명. **공식 표기 그대로** (7장) |
| `name_en` | string | | 영문 제품명 |
| `grade_family` | string | O | 6.2의 목록 중 하나 |
| `scale` | string | O | `1/144` `1/100` `1/60` `논스케일` |
| `series` | string | | 작품명 |
| `unit_model_numbers` | string | | 기체 형식번호. 여러 개면 `;` 구분 |
| `base_kit_temp_id` | string | | **외형 변형**의 원본 킷 |
| `parent_kit_temp_id` | string | | **확장 파츠·무장 세트**의 대상 킷 (신설) |
| `is_limited` | boolean | O | |
| `limited_channel` | string | | `프리미엄반다이` `건담베이스` `이벤트` `일반` |
| `data_source` | string | O | 출처 도메인 |
| `confidence` | string | O | `high` / `medium` / `low` |

**`product_no`, `release_date`, `price_jpy`가 이 파일에서 빠졌다.** 재판마다 달라지므로 `kit_releases.csv`로 이동한다.

### 6.2 `grade_family` 허용값

```
HG   RG   MG   MGEX   MGSD   PG   EG   RE100   FM   SD   구판
```

- HGUC, HGCE, HGAC, HGBF, HGIBO, HGWFM 등 **모든 HG 계열은 `HG`**. 접미어의 작품 정보는 `series`가 담당
- SDCS, BB전사, SD EX-STANDARD, 크로스실루엣 → `SD`
- PG Unleashed → `PG`
- **MGSD는 독립 값.** MG나 SD로 넣지 않는다
- Full Mechanics → `FM` / RE/100 → `RE100`
- 등급 표기 없는 구판 1/144, 1/100 → `구판`

### 6.3 `kit_releases.csv` (신설)

초판과 재판을 분리해 담는다. 킷 하나에 여러 행이 올 수 있다.

| 컬럼 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `kit_temp_id` | string | O | `kits.csv` 참조 |
| `release_date` | date | O | `YYYY-MM-DD`. 일자 미상이면 `YYYY-MM-01` |
| `price_jpy` | integer | | 해당 발매 시점 정가 |
| `product_no` | string | | 5장의 규칙 적용. 미확인이면 공란 |
| `is_first` | boolean | O | 초판이면 `true` |
| `confidence` | string | O | |

**최소 요구** — 킷마다 `is_first=true` 행이 하나는 있어야 한다. 재판 정보는 확인되는 것만 추가한다. 재판을 찾지 못해도 문제없다.

### 6.4 `units.csv` — 누적 단일 파일

**차수별로 나누지 않는다.** 하나의 파일에 계속 추가한다.

새 기체를 만들기 전에 `model_number`가 이미 있는지 확인한다. 있으면 새로 만들지 않는다.

| 컬럼 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `model_number` | string | O | ASCII 정규화 표기 (7장) |
| `model_number_official` | string | | 특수문자 포함 정식 표기 (신설) |
| `name_ko` | string | O | **국내 통용 명칭** |
| `name_ja` | string | | 공식 표기 그대로 |
| `name_en` | string | | |
| `series` | string | | |

### 6.5 `coverage_checklist.md`

4장 참조. **CSV와 함께 반드시 제출한다.**

### 6.6 `notes.md`

판단이 애매했던 케이스, 소스 충돌과 채택 근거, 수집 불가 구간과 이유, 목록과 CSV 행 수 불일치 내역.

## 7. 표기 정규화 규칙 (신설)

v1에서 같은 기체가 여러 표기로 갈렸다.

### 7.1 일본어 표기는 공식 표기를 그대로 쓴다

가타카나로 바꾸거나 대체 문자를 쓰지 않는다.

```
올바름   νガンダム       Hi-νガンダム
틀림     ニューガンダム   ニュ－ガンダム
```

전각 하이픈(`－`)을 반각(`-`)이나 장음부(`ー`) 대신 쓰지 않는다.

### 7.2 형식번호는 두 컬럼으로 나눈다

특수문자가 들어가는 형식번호가 있다. 시스템 처리를 위한 정규화 표기와 정식 표기를 모두 남긴다.

```
model_number            RX-93-V2        ASCII 정규화. 대문자, 하이픈 유지
model_number_official   RX-93-ν2        정식 표기
```

정규화 규칙 — 그리스 문자는 가장 가까운 라틴 문자로(`ν`→`V`), 나머지는 대문자 알파벳·숫자·하이픈·대괄호만 남긴다.

### 7.3 국내 통용 명칭을 쓴다

`name_ko`는 국내 커뮤니티에서 실제로 쓰는 이름을 쓴다. 영문 약어를 그대로 두지 않는다.

```
올바름   징크스
틀림     GN-X
```

킷 이름과 기체 이름이 어긋나지 않게 한다. `units.csv`의 `name_ko`와 `kits.csv`의 제품명 표기를 맞춘다.

## 8. 예외 처리 규칙

| 케이스 | 처리 |
|---|---|
| **재판** | `kits.csv`에 행을 만들지 않는다. `kit_releases.csv`에 행 추가 |
| **외형 변형** (클리어, 코팅, 애니메컬러) | 별도 킷. `base_kit_temp_id` 연결 |
| **유통 한정** | 별도 킷. `is_limited=true` + 채널 기입 |
| **확장 파츠·무장 세트** | 별도 킷. `unit_model_numbers` 비우고 `parent_kit_temp_id` 연결 |
| **파츠 세트 성격의 변형** (클리어 바디 파츠 등) | 완제품이 아니면 확장 파츠로 취급. `parent_kit_temp_id` 사용 |
| **세트 킷** (기체 복수) | 한 행. `unit_model_numbers`에 `;` 나열 |
| **변칙 스케일** (HG 1/100 등) | 제외하지 않는다. 실제 값 기입 |
| **패키지 변형** (라이트 패키지 등) | 구성이 다르면 별도 킷. 같으면 `kit_releases` |
| **발매 예정** | 포함. `confidence=low` |
| **발매 취소** | 제외 |
| **정보 부족 구판** | **반드시 포함.** 아는 필드만 채우고 `confidence=low` |

**판단 원칙** — 넣을지 말지 애매하면 **넣는다.** 값을 쓸지 말지 애매하면 **비운다.**

## 9. 소스 우선순위

1. 제조사 공식 제품 정보
2. 유통사 상품 페이지 (품번, 정가, 발매일에 강함)
3. 영문 위키 계열 중 CC BY-SA 라이선스 — **사실 필드만**

소스가 충돌하면 위 순서로 채택하고 `notes.md`에 기록한다.

## 10. 작업 순서

**등급 하나씩. 각 등급마다 4장의 3단계를 완주한 뒤 다음으로 넘어간다.**

```
1차: MG        (물량 최대. 여기가 제대로 되면 나머지는 쉽다)
2차: RG
3차: PG, MGEX, MGSD, RE100, FM, EG
4차: SD 계열
5차: 구판
```

v1과 순서를 바꿨다. MG가 물량이 가장 크고 전수 수집이 가장 어려우므로 먼저 부딪힌다.

**MG 4-1단계(목록)를 마치면 멈추고 검증받는다.** 목록이 200종을 넘지 않으면 누락이 있다는 뜻이다.

## 11. 검증

### 형식

- [ ] `coverage_checklist.md` 항목 수 = `kits.csv` 행 수
- [ ] `grade_family`, `scale` 허용값 이탈 0건
- [ ] `temp_id` 중복 0건
- [ ] `base_kit_temp_id`, `parent_kit_temp_id` 참조 유효
- [ ] `unit_model_numbers`가 전부 `units.csv`에 존재
- [ ] `units.csv` 내 `model_number` 중복 0건
- [ ] 모든 킷에 `is_first=true` 릴리스 행 존재
- [ ] 서술 문장·이미지 URL 혼입 0건

### 내용

- [ ] **품번을 기입한 행 중 10건을 무작위로 골라 출처 페이지에서 대조**
- [ ] 파생 킷과 원본의 품번이 연번인 경우가 있는가 → 전부 재확인
- [ ] `name_ja`에 전각 하이픈, 가타카나 대체 표기가 있는가
- [ ] 같은 기체를 가리키는 `name_ko`가 파일 간 일치하는가

내용 검사 첫 항목이 실질적인 품질 게이트다. 반드시 수행한다.

## 12. 하지 말 것

- 스키마에 없는 컬럼 추가
- **확인하지 못한 값을 그럴듯하게 채우기** (품번, 발매일, 가격)
- **파생 킷 품번을 원본에서 유추하기**
- 제품명 임의 축약·통일
