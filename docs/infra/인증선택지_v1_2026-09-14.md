## 2. 확인한 제약

### 2.1 무료 Workers에서 비밀번호 해시가 CPU 한도에 걸린다

- 무료 Workers는 요청당 CPU 10ms
- Better Auth 기본 비밀번호 해시(순수 JS scrypt)는 약 80ms 수준으로 보고됨. 가입이 간헐적으로 CPU 한도 초과로 실패하는 이슈가 있었다(#8860, 2026-03, 닫힘)
- 우회책은 Workers 내장 `node:crypto` scrypt로 해시 함수를 교체하는 것. **10ms 안에 드는지 실측 자료는 찾지 못했다 (미확인)**

→ 비밀번호 로그인을 넣으려면 먼저 실측이 필요하다. #29로 MVP에서는 피했다.

### 2.2 메일 발송은 비용과 공격 경로를 늘린다

| 서비스 | 조건 |
|---|---|
| Cloudflare Email Service (발송) | **Workers 유료 플랜 필요.** 월 3,000통 포함, 이후 1,000통당 $0.35 |
| Resend 무료 | 월 3,000통, **하루 100통 상한.** 초과 시 발송 중지 |

가입 인증·비밀번호 재설정 메일은 남의 주소로 연발하는 공격 대상이다(비용 어뷰징 방어 2장 #7). 하루 100통 상한이면 공격 하루에 정상 가입이 막힌다.

→ 소셜 전용이면 이 벡터가 사라진다.

### 2.3 한국 소셜 로그인 지원

| | 카카오 | 네이버 | 구글 |
|---|---|---|---|
| Better Auth | 내장 | 내장 | 내장 |
| Supabase Auth | 내장 | **미지원** (요청 토론만 있음) | 내장 |
| Clerk | 내장 없음. 커스텀 OIDC 연결 | 커스텀 연결이 OIDC 기준이라 **어려울 가능성** (네이버는 OIDC 미지원으로 알려짐, 2차 자료) | 내장 |

**카카오 이메일** — `account_email` 동의항목은 비즈 앱에서만 받는다. 사업자 없는 **개인 개발자도 본인인증 + 심사로 비즈 앱 전환 가능.** 심사 전에는 이메일 없이 카카오 고유 ID로만 식별한다.

## 4. 소셜 전용(#29)의 대가와 완화

| 대가 | 완화 |
|---|---|
| 소셜 계정을 잃으면 G-MOIM 계정도 잃음 | 로그인한 상태에서 소셜 여러 개를 한 계정에 연결할 수 있게 한다 |
| 소셜 계정이 없는 사람은 가입 불가 | 한국에서 셋 다 없는 경우는 드물다고 판단. 요청이 쌓이면 이메일 일회용 코드 추가 |
| 카카오 이메일은 비즈 앱 심사 필요 | 이메일을 식별자로 쓰지 않는다. 유저 식별은 우리 `users.id` |
| 제공자가 로그인 정책을 바꾸면 영향 | 제공자 셋을 두어 하나가 막혀도 연결된 다른 제공자로 로그인 |

**이메일로 자동 연결하지 않는다.** 서로 다른 제공자에서 같은 이메일이 왔다고 같은 사람으로 합치면, 이메일 검증이 느슨한 제공자를 통해 남의 계정을 가로챌 수 있다. 연결은 **로그인한 본인이 직접** 한다.

## 5. 데이터 구조 원칙

- Better Auth의 유저 테이블이 곧 우리 `users`다. `users.id`는 우리가 발급한다
- 카카오·네이버·구글 고유 ID는 **연결 계정 테이블에만** 둔다
- 작례·이미지·쿼터 등 도메인 테이블은 **`users.id`만 참조**한다. 제공자 ID를 참조하지 않는다
- 세션은 Postgres에 저장. 요청마다 세션 조회 쿼리가 나가면 Hyperdrive 일 10만 한도를 소모하므로, 쿠키 캐시 등 조회 횟수를 줄이는 설정을 쓴다 (**구현 시 확인**)

## 6. 캐시와 로그인 상태 (#30)

작례 페이지는 SSR + Workers Cache다(#18). 캐시된 HTML은 모든 방문자에게 같은 내용이 나간다.

- 캐시되는 HTML에 "OOO님", 내 글 수정 버튼, 로그인 여부 분기를 넣으면 **다른 사람에게 내 화면이 캐시되어 나간다**
- 로그인 상태가 필요한 부분은 island로 빼서 브라우저에서 따로 조회한다
- 로그인 쿠키가 있는 요청이라고 캐시를 우회하지 않는다. 우회하면 로그인 유저 수만큼 렌더 비용이 든다

## 7. 이전 방법 (#19)

"Better Auth를 빼고 다른 곳으로 옮기려면"

- 유저·연결 계정 테이블이 우리 DB에 있으므로 **데이터 이관은 없다.** 새 인증 수단이 같은 테이블을 읽게 하거나, 제공자 ID를 새 테이블로 옮기는 SQL 한 번
- 비밀번호가 없으므로 해시 형식 호환 문제가 없다
- 카카오·네이버·구글 앱 설정의 콜백 URL만 새 경로로 바꾼다
- 기존 세션은 무효화되어 전원 재로그인 1회
