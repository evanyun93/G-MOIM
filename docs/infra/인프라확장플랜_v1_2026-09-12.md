# 인프라 확장 플랜 v1

무료 티어에서 시작해 유저 증가에 따라 단계적으로 확장하기 위한 가이드.

작성 2026-09-12 · 무료 티어 수치 확인 2026-09-12

> **주의** — 무료 티어 조건은 자주 바뀐다. 실제 결정 전에 각 벤더 공식 페이지에서 재확인할 것. 이 문서의 수치는 작성 시점 기준이며, 확인 없이 신뢰하지 말 것.

---

## 1. 원칙

**비용 곡선의 기울기를 낮추는 게 목표다.** 비용을 0으로 유지하는 게 아니라, 유저가 10배 늘 때 비용이 10배가 되지 않게 하는 것. 설계 문서 부록 C의 연장.

**미리 확장하지 않는다.** 단계마다 명확한 트리거 지표를 두고, 지표가 걸릴 때만 움직인다. 유저 0명일 때 확장 대비를 하면 그건 그냥 낭비다.

**되돌리기 어려운 것만 미리 정한다.** 스토리지 선택, URL 구조, 이미지 파이프라인은 나중에 바꾸면 비싸다. 나머지는 그때 가서 정한다.

## 2. 0단계 — 무료 구성 (시작 지점)

| 레이어 | 선택 | 무료 한도 | 비고 |
|---|---|---|---|
| 정적 호스팅 | Cloudflare Pages | 빌드 500회/월, 정적 요청 무제한 | |
| 서버 렌더링 | Cloudflare Workers (Pages Functions) | **100,000 요청/일**, CPU 10ms/요청 | 실질적 첫 병목 |
| 이미지 저장 | Cloudflare R2 | 10GB, Class A 100만·Class B 1000만 op/월 | **egress 요금 없음** |
| DB | Neon (권장) 또는 Supabase | Neon: 프로젝트당 0.5GB, 100 CU-hour/월, scale-to-zero | |
| 도메인 | 유료 (연 1~2만원) | — | 유일한 고정 지출 |
| CDN | Cloudflare (기본 포함) | 대역폭 사실상 무제한 | 단, 동영상·대용량 파일 호스팅은 ToS 위반 |

### DB는 Neon을 권한다

Supabase 무료 티어는 **1주간 활동이 없으면 프로젝트가 일시정지**되고 수동으로 깨워야 한다(2026년 2월에 강화됨). 공개 전 개발 기간이 길고 방문자가 없는 G-MOIM 상황에서는 이게 매번 걸린다.

Neon은 scale-to-zero라 콜드 스타트는 있어도 정지되지 않고, 무료 프로젝트 수도 넉넉해서 개발용과 운영용을 나눠 쓸 수 있다.

다만 Supabase는 인증·파일 저장·실시간이 묶여 있어서 직접 붙일 게 적다. 인증을 직접 만들기 싫으면 Supabase가 편하다. Neon도 2026년 7월에 인증·오브젝트 스토리지를 베타로 냈지만 베타다.

**판단 기준** — 인증을 붙이는 데 드는 시간 vs 매주 프로젝트를 깨우는 번거로움. 둘 중 뭐가 더 싫은지로 고르면 된다.

### 이 구성으로 얼마나 버티나

500MB Postgres는 생각보다 크다. 킷 5천 개 + 별칭 2만 개 + 작례 텍스트는 다 합쳐도 수십 MB 수준이다. **DB 용량은 한동안 문제가 안 된다.**

진짜 한도는 이미지와 요청 수다. 부록 C대로 장변 2048px WebP 변환을 적용하면 이미지 한 장이 300KB 안쪽이므로, R2 10GB면 대 **3만 장**이다. 작례 하나에 사진 10장이면 작례 3천 개분. 초기에는 남는다.

## 3. 무엇이 먼저 깨지는가

깨지는 순서를 알면 대비 순서가 정해진다.

| 순위 | 한도 | 예상 도달 시점 | 증상 |
|---|---|---|---|
| 1 | **Workers 100K 요청/일** | 일 방문자 2~5천 명 부근 | SSR 페이지가 죽음 (1101 에러) |
| 2 | **R2 10GB** | 작례 3천 개 부근 | 업로드 실패 |
| 3 | **Neon 100 CU-hour/월** | 트래픽이 상시화될 때 | 쿼리 지연·차단 |
| 4 | **DB 0.5GB** | 작례 수만 개 이상 | 쓰기 실패 |
| 5 | CDN 캐시 미스 비용 | 크롤러 유입 시 | 원본 서버 부하 |

**1번이 압도적으로 먼저 온다.** 정적 자산은 무제한인데 SSR은 Workers 요청을 소모하고, 부록 F에서 킷·기체·작례 페이지를 SSR로 하기로 했기 때문이다. 페이지 하나 열 때 API 호출과 이미지 변환이 각각 카운트되면 방문자 1명이 요청 5~10건을 쓴다.

### 1번을 늦추는 방법 (돈 안 드는 것부터)

- **킷·기체 페이지를 정적 생성으로.** 킷 데이터는 거의 안 바뀐다. 작례가 추가될 때만 재생성하면 SSR이 필요 없고, 정적 자산은 무제한이다. **이게 가장 효과가 크다**
- 캐시 헤더를 길게. 같은 페이지 재방문이 요청을 안 쓰게
- 이미지 변형을 유한한 프리셋으로 고정해 캐시 파편화 방지
- 크롤러 차단. AI 학습 크롤러가 요청 수를 조용히 먹는다
- API 라우트 통합. 페이지 하나에 호출 하나

> **설계 반영 필요** — 위 첫 항목은 4.1 스택 선정에 직접 영향을 준다. 킷·기체 페이지를 ISR/SSG로 낼 수 있는 프레임워크를 고르는 게 무료 티어 수명을 몇 배로 늘린다. 전면 SSR을 전제로 스택을 고르면 트래픽이 붙는 순간 바로 유료 전환이다.

## 4. 단계별 확장

### 1단계 — 첫 유료 전환 (월 $5~10)

**트리거** — Workers 요청이 일 7만 건을 넘기기 시작(한도의 70%). 또는 R2 저장이 8GB를 넘김.

**조치**

- Workers Paid $5/월. 월 1000만 요청 포함, 초과분 100만당 $0.30. 일일 하드캡이 사라지는 게 핵심
- R2 초과분은 GB당 월 $0.015 수준으로 저렴. 100GB 써도 월 $1.5 안팎. **egress가 무료라 여기는 안 무섭다**

**예상 월 비용** $5~10. 도메인 포함해도 만원 남짓.

이 단계가 가장 오래 간다. 서두를 필요 없다.

### 2단계 — DB 전환 (월 $25~45)

**트리거** — Neon CU-hour 소진, 또는 DB 0.5GB 접근, 또는 쿼리 지연이 체감될 때.

**조치**

- Neon Launch(약 $19/월) 또는 Supabase Pro($25/월)로 전환
- 이 시점에 인덱스를 점검할 것. 대개 플랜 업그레이드보다 인덱스 하나가 효과가 크다
- 전문 검색이 무거워지면 pg_bigm 인덱스 재검토(Neon 미지원 — 이 단계의 DB가 지원하는지 먼저 확인, #40). 아직 Elasticsearch는 도입하지 않는다

**예상 월 비용** $25~45.

> **여기서 착각하기 쉬운 것** — 느려진 원인이 플랜인지 쿼리인지 먼저 확인할 것. 쿼리 문제를 플랜으로 덮으면 다음 단계에서 더 크게 터진다.

### 3단계 — 구조 전환 (월 $100~300)

**트리거** — 일 방문자 2만 명 이상, 또는 이미지 1TB 이상, 또는 DB 단일 인스턴스로 쓰기가 밀릴 때.

**조치 후보** (전부 다 할 필요 없음, 병목에 해당하는 것만)

- 읽기 복제본 추가. 킷·작례 조회가 읽기 위주라 효과가 큼
- 이미지 원본을 콜드 스토리지로 분리. 서빙본만 R2 핫에
- 검색 분리 검토. 이 단계에서 처음으로 Elasticsearch/Meilisearch가 정당화됨
- 모더레이션 LLM 호출 비용이 유의미해지므로 부록 A의 계층 구조를 실제로 튜닝

**예상 월 비용** $100~300. 이 지점이면 광고나 멤버십(6.1, 6.2)을 실제로 검토할 시점이다.

### 4단계 — 그 이상

여기까지 오면 이 문서는 쓸모없다. 그때의 실제 데이터로 다시 쓸 것.

단계 전환은 감이 아니라 지표로 판단한다. 주 1회 확인.

| 지표 | 확인처 | 경고선 |
|---|---|---|
| Workers 일일 요청 수 | Cloudflare 대시보드 | 7만/일 |
| R2 저장 용량 | Cloudflare 대시보드 | 8GB |
| R2 Class A 오퍼레이션 | Cloudflare 대시보드 | 70만/월 |

| DB 컴퓨트 사용량 | Neon 콘솔 | 70 CU-hour/월 |
| 캐시 히트율 | Cloudflare Analytics | 85% 미만이면 조사 |

경고선은 한도의 70% 수준으로 잡았다. 갑자기 막히는 것보다 미리 아는 게 낫다.

## 6. 되돌리기 어려운 결정 (지금 정해야 하는 것)

확장은 나중에 해도 되지만 아래는 미루면 비싸진다.

**스토리지는 R2로.** S3 계열은 egress 과금이라 이미지 커뮤니티에서 트래픽이 늘수록 비용이 급증한다. 나중에 옮기려면 전체 이미지를 이관하고 URL을 전부 바꿔야 한다. 처음부터 R2.

**이미지 URL은 불변으로.** 콘텐츠 해시 기반 키를 쓰고 한 번 발급한 URL은 바꾸지 않는다. 캐시 효율의 전제이자 이관 시 안전장치.

**원본을 서빙 경로에 두지 않는다.** 업로드 시점에 변환하고, 원본은 아예 안 받거나 별도 격리. 나중에 소급 변환하려면 전체 재처리가 필요하다.

**EXIF 제거는 업로드 파이프라인에.** 법무 요건(부록 B)이자, 나중에 하면 이미 올라간 사진의 GPS가 이미 노출된 뒤다.

**킷·기체 페이지의 정적 생성 가능성.** 3장에서 설명한 대로 무료 티어 수명을 좌우한다. 스택 선정(4.1) 시 제약 조건으로 넣을 것.

**URL 슬러그와 slug_history.** 설계 문서 부록 F 참조. 도메인 이전이나 구조 변경 시 색인 손실을 막는다.

## 7. 도메인

유일하게 처음부터 나가는 고정 비용. 연 1~2만원.

- 공개 전이라도 미리 확보할 것. 나중에 선점당하면 브랜드가 꼬인다
- Cloudflare Registrar는 원가 판매라 갱신 시 가격이 안 뛴다
- 공개 전까지는 전체 `noindex`. 미완성 페이지가 색인되면 부록 F의 전략이 처음부터 꼬인다

## 8. 재검토 시점

이 문서를 다시 열어야 하는 때.

- 모니터링 지표 중 하나가 경고선에 닿았을 때
- 공개(홍보)를 시작하기 직전 — 트래픽이 처음으로 예측 불가능해지는 시점
- 6개월이 지났을 때 — 무료 티어 조건이 바뀌었을 가능성이 높다
- 스택 선정(4.1)을 확정할 때 — 3장의 정적 생성 제약을 반영해야 함
