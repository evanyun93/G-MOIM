## #13. "목록은 살린다"를 하루 만에 철회했다 — Antigravity 1차 결과물 전면 반려

**상황**
Antigravity가 MG 목록 게이트에서 멈추지 않고 MG CSV, RG, PG까지 진행했다(627 / 226 / 26행). 어제 1차 점검에서는 "목록은 살리고 CSV만 다시"를 권장했다. 오늘 수치로 다시 세어보고 판단을 정해야 했다.

**선택**
전부 반려. 파일은 `_rejected_2026-09-13/`으로 옮겨 누락 대조에만 쓰고, MG 목록부터 01b 지시서로 재작업. RG·PG는 MG 통과 후.

**당시 근거**
- MG 제품명에 일본어 위키백과 서술 문장 77행. CC BY-SA 서술 혼입이라 절대 제약 위반
- 품번·시리즈·형식번호가 세 등급 전 행 공란, 전 행 `confidence=low`, `units.csv` 0행. 행 수만 맞춰놓고 "1:1 완벽 일치, 누락 없음"이라 보고
- 목록을 살릴 수 없는 이유 — 달롱넷·위키백과·fandom 표기가 섞여 `RX-78 v1.0`, `Zaku II 샤아전용`, `ガトー専用ゲルググ`가 한 목록에 있다. 기준 표기가 없으니 중복인지 판정할 방법이 없다. 어제는 행 수와 커버리지 표만 보고 목록이 쓸 만하다고 봤다
- 재작업 방식은 **공식 라인업 하나를 뼈대로, `name_ja` 공식 표기를 중복 판정 키로.** 여러 소스를 동시에 섞은 것이 뒤섞임의 원인이라 판단

**반대 의견**
627종이라는 물량은 옛 358종보다 크고, 한정판 전수 조사는 실제로 일부 해냈다. 버리면 시간 손실이 크다. 표기만 사후 정규화하면 된다. → 표기 정규화 자체가 공식 표기를 다시 찾아야 하는 작업이라 새로 만드는 것과 비용이 비슷하다. 옛 목록은 누락 대조에 쓰니 물량 정보는 잃지 않는다.

**미판정 질문**
- 01a에 "멈춤"을 표로, 굵게, 두 번 썼는데 세 번 넘었다. 01b에 "넘으면 안 보고 반려"를 적었지만 **문서로 게이트를 지키게 할 수 있나.** 한 번에 한 단계만 담긴 지시를 주는 게 맞는 방식일 수 있다
- 2018년 이후 MG 일반 유통이 연 1~3종으로 급감한 것이 실제인지, 달롱넷 목록이 끊긴 구간을 "적다"로 쓴 것인지. 재작업 결과로 판정된다
- 공식 사이트(bandai-hobby.net)가 과거 제품까지 빠짐없이 싣고 있나. 뼈대 소스가 틀리면 01b 방식 전체가 흔들린다

## #14. 스타일링은 Tailwind v4, 색은 CSS 변수 토큰으로만

**상황**
4.1.5. 후보는 Tailwind v4, Astro 스코프 CSS + CSS 변수(도구 없음), UnoCSS.

**선택**
결정 #27. Tailwind v4. 색·간격·글꼴은 `src/styles/`의 CSS 변수 토큰으로만 정의하고 컴포넌트는 토큰 클래스만 쓴다. 글 본문은 typography 플러그인.

**당시 근거**
코드를 쓰는 AI가 둘이다(메인 세션, Antigravity의 킷 페이지). 클래스 이름을 각자 짓게 두면 스타일이 갈라진다. Tailwind는 AI가 가장 일관되게 쓰는 문법이다. 블로그 스킨(1.1.5)은 컴포넌트가 토큰만 참조하면 변수 교체로 끝난다.

**반대 의견**
스코프 CSS는 의존성이 0이고 이식성이 가장 높다. Tailwind는 마크업이 길어지고 빌드 도구가 하나 는다. → CSS는 벤더 잠금이 아니라 빌드 도구라 #19 위험이 작다고 봤다. 토큰이 CSS 변수라 Tailwind를 빼도 토큰은 남는다.

**미판정 질문**
- "색 값 직접 쓰기 금지"를 AI가 실제로 지키나. `bg-[#...]` 임의값은 Tailwind가 막지 않는다. 린트로 강제해야 할 수 있다
- 유저가 쓴 글 본문(`prose`)과 사이트 UI 토큰이 스킨 교체 시 같이 바뀌나, 따로 노나
